# Expressibility gaps

What the corpus helpers could not say in VCL, or only by a workaround (`docs/corpus-plan.md`). The count per
kind is what Stage B reads to decide which ops and functions to add. A gap is a fact about the language, not
a mistake of the helper. The "wording" table lists prompt sentences that misled a helper; they
are fixed together at the end of Phase 6 so the Orchestrator is updated once.

## Gaps in the language

| Pair | Could not do | What the spec does instead |
| --- | --- | --- |
| c013 | month arithmetic ("12 months before today") | `TODAY - 365`, on an ASSUME line |
| c015 | read the fill of a cell (so a macro cannot keep a highlight a person added) | clears every fill it owns on each run, on an ASSUME line |
| c019 | a `reldates` fixture column cannot hold text such as "TBC" | "no valid date" is tested with blank cells only |
| c023 | DEDUPE cannot trim its keys | a two-pass count dictionary with a `dir=up` loop |
| c028 | a SET_FORMULA formula cannot name a sheet whose name has spaces ("Calibration Tracker") | names `CalibrationTracker` and tells the user to rename the tab if it differs |
| c030 | FILTER keeps the rows equal to one value; it cannot hide only the Closed rows | keeps only Open rows, so blank or other statuses are hidden too |
| c030 | no TEST can prove that a row that was reopened shows again (a TEST cannot change a cell between runs, a fixture cannot start with hidden rows) | `runs=2` proves only that a re-run is safe |
| c034, c039, c051 | one fixture column that holds real numbers and non-numbers together (`+boundary` on `int()` or `num()` takes numbers and "" only; `values()` takes quoted text only and stores it as text) | two FIXTURE files, one with numbers and blanks, one with text values such as "n/a" |
| c036, c037, c038 | write rows in key order, or sort a dictionary's keys | writes the rows in first-seen order, then `SORT(USED_RANGE($out))`; every row-counter mutant is then equivalent, because the SORT moves the gap rows down |
| c039, c040, c051, c052 | a set: a dictionary needs a value and a mode on every `DICT_ADD` | `1, mode=keep`; the mode and value mutants are equivalent because only `EXISTS` reads it |
| c043 | the last used row of a sheet, MAX, and "is this row empty" | `LOOP_COLS` over the header columns with `LASTROW` and a flag; the one `>` mutant is equivalent |
| c044 | DEDUPE cannot trim its keys (case is folded already) | an ASSUME says " NCR-003" and "NCR-003" stay different |
| c049 | FIND limited to one column (no column range, and RANGE refuses whole columns) | `FIND(USED_RANGE(...))` with an ASSUME that the NCR number appears only in the NCR No column |
| c050 | the latest value per key (DICT_ADD has no max or latest mode) | `DICT_GET` + `IS_DATE` + compare + overwrite; two equivalent mutants |
| c050 | ROUND, or a percentage | a fraction shown with `FORMAT numfmt="0.0%"`; the fixture counts make every rate exact in binary |
| c057 | build a summary sheet that is made on the first run and rebuilt on every later run (rule 22: only the run that adds a sheet may write to it) | the summary sheet is an argument, ASSUMEd to exist, and rebuilt with CLEAR and WRITE_ROW on every run |
| c057 | alphabetical order of a dictionary's keys (KEYS walks in first-seen order) | writes the rows, then `SORT(USED_RANGE($out), key=1, order=asc, header=yes)` |
| c057 | a `reldates` fixture column that holds text (`+boundary` takes day numbers and blanks only) | "no valid Expiry Date" is tested with blank cells in quals_01 and a second fixture file whose whole Expiry Date column is `text(10)` |
| c068 | a formula's text cannot call COL(), and a TEST can check only the formula text (FORMULA), never the value it computes | PRE pins Planned Date to column 2 and Actual Date to column 3, each cell gets the R1C1 text `=IF(RC3="","",RC3-RC2)` in a LOOP_ROWS, and a second fixture with the columns swapped expects RESULT = -1 |
| c058, c070 | "write/rebuild a summary sheet": create the sheet if it is missing and also rebuild it on every run (rule 22; a BUILD cannot hand a freshly made sheet on, because CALL passes only the caller's own $arguments) | the output sheet is an argument, ASSUMEd to exist, cleared and rebuilt; the helper added a PRE of its own (`COL($out, "PQR Ref") = 0`, `COL($out, "Heat No") = 0`) so a register passed as `out` by mistake is left alone, which nobody asked for |
| c070 | which spelling a dictionary key keeps when later DICT_ADDs differ in case or spaces | stores the cleaned first spelling as the value with `mode=keep` and writes that value, so no TEST depends on how keys are folded |
| c060 | a `reldates` fixture column that holds text such as "TBC" | a separate `values(...)` fixture holds the text dates (same gap as c019 and c057) |
| c054 | "clear old highlights first" as a block clear: the prompt does not say whether RANGE's A1 reference can be built at run time (for example "A2:D" & last row) | clears each row's fill inside the one loop (`FORMAT fill=none`, then green or red), so the heading row keeps any fill it had |
| c063 | one FIXTURE column that holds text dates and real dates together (`+boundary` on a `reldates` column takes only day numbers and ""; there is no documented way to put text in a `dates()` column; V262 rejected the text) | two fixture sheets with the same headings, PlannedText (text dates, blanks and other text in Planned Date, real dates in Actual Date) and ActualText (the reverse), and the same macro runs on both (same gap as c019, c057, c060) |
| c063 | what display format SET_VALUE gives a converted date, and whether a Text-formatted cell accepts one | the cells keep their number format; adding `FORMAT numfmt` would force a whole-sheet MODIFIES and lose the automatic collateral check |
| c063 | a TEST assertion that tells a real date from date-looking text (`VALUE(cell) = "2026-03-05"` is TRUE for both) | proved by `runs=2` with RESULT = 0 (the second run finds nothing left) and an exact RESULT count on the first run |
| c069 | read row visibility in a Function (VISIBLE_COUNT is an assertion function only) | returns the number of rows whose Result is SAME as "Reject", which equals the visible count only because FILTER uses the same SAME test |
| c061, c064 | "On a No WPS / Rejected Welds sheet ...": create the output sheet if it is missing and also rebuild it every run (rule 22) | the output sheet is an argument, ASSUMEd to exist (same as c057, c058, c059, c070) |
| c061, c064 | copy a cell's number format (VCL has no op for it) | the Expiry Date and Report Date values are copied with WRITE_ROW and rely on Excel's default date format on assignment; TESTs check values only |
| c065 | a numeric FIXTURE column that also holds non-numeric text (`+boundary` on `int()`, `num()`, `seq()` and `dates()` takes numbers or dates and "" only; V262) | grn_01 covers blank quantities with numeric ones, and grn_02 holds text-typed quantities ("TBC", "n/a", "20") built with `values()`, so the output cells hold the original text |
| c065 | "On a Short Receipts sheet ...": create the output sheet if it is missing and rebuild it every run (rule 22) | the output sheet is an argument, ASSUMEd to exist (same as c057, c058, c059, c061, c064, c070) |
| c066 | the request names four statuses (Copied, Already there, Missing, Bad name), but COPY_FILE also gives Conflict, Locked and Too long, and in Excel Check copy and Failed | Status shows the op's own word, stated in an ASSUME; the fixture includes Conflict and Locked rows |
| c067 | "if the file holds a different number, update it": WRITE_TEXT never overwrites | a different existing number gives status Conflict in G1 and the file is left unchanged (ASSUMEd); a real gap, because the file can go stale |
| c067 | a spaces-only Actual Date cell in a `dates()` fixture | counts as missing (IS_EMPTY semantics, on an ASSUME) but no TEST covers it, because a `dates()` column cannot hold a spaces-only cell |
| c071, c072 | "on a ... sheet" for every output sheet of a BUILD, rebuilt each run (rule 22) | all the output sheets are arguments and the spec ASSUMEs that every sheet exists (five in c071, three output sheets in c072); it cannot create them on a first run |
| c072 | the request names a "Flag column" that is not among the ITP Tracker's columns | found with COL; if it is missing the spec adds the heading after the last used header in row 1 (SET_VALUE to row 1, the rule 14 exception), which forces `MODIFIES $itp` for the whole sheet and weakens the automatic "nothing else changed" check; compensated with PRE_COUNTA TESTs on the other columns and a second fixture file (insp_02, no Flag column) that tests the heading |
| c072 | a Report Date typed as text in a sort | ASSUMEs real dates, because text sorts unpredictably (text before numbers when descending); no TEST covers it |

## Wording of the prompt to fix

| Pair | Sentence | Problem |
| --- | --- | --- |
| c021 | rule 19: "repeat dictionary keys with +dupes(<n>) or values() counts of 2 or more" | different spellings of one key (" h-100 " and "H-100") do not count; the first data row must change the result |
| c025 | rule 19: "at least one blank cell" | V059 wants one in every FIXTURE sheet of every file the SKIP_IF reads |
| c026 | FIXTURE: "+boundary(v1,v2,...) the first data rows hold exactly these values" | every boundary value must also be in `values(...)`, listed no more often than its count (V264) |
| c028 | FIXTURE: "They may be short forms of the real sheet names" | a formula needs the sheet's exact name, so a short form does not work in SET_FORMULA |
| c031, c032 | rule 9 ("One macro or one tool is no reason for a BUILD") against Example 4 ("Make it one tool I can start with one macro") | Example 4's request invites a BUILD that one TASK would do |
| c032 | rule 5: "swap two of the sheets RunHeadless takes" | swap two whose headings differ, or the PRE still passes |
| c019 | rule 15: "guard ... in a nested IF" | SEMANTICS says SKIP_IF NOT IS_DATE(x) guards too |
| c033, c039 | rule 19: "(a "" boundary value in an early row, or +blank(<n>); LASTROW ignores a blank in the last row)" | a `LASTCOL($ws, 1)` mutant survives unless a data row is narrower than the header (a trailing column blank in row 2); and a blank key in the last row means the loop never visits that row |
| c036, c037, c051 | rule 19: "stale=<n> rows" (and Example 4's `stale=2`) | stale must be larger than the number of rows the macro writes, or a deleted CLEAR survives (raised to 6 and 8) |
| c034, c039, c050, c051 | FIXTURE: "+boundary(...) the first data rows hold exactly these values" and "for values(...) the values move up, so the counts stay the same" | a boundary value must fit the column rule (V262: `int()` and `num()` take numbers only) and the list must be the same multiset as the `values(...)` counts (V264); text is possible only with `values()`, which stores text (V033 for bare numbers); the form of a date in `+boundary` for `dates(...)` is not given |
| c042, c043 | rule 15: "Guard with the check itself ..., never with a flag variable set earlier" | read as banning every flag; it only concerns a guard, and a Boolean that is not a guard (`hasOther`) avoids counter mutants such as `+ 1` to `+ 2` |
| c042, c043, c044 | rule 5: "When the test workbook has another sheet, add a wrong-sheet TEST" | unclear whether a spec should add a Notes sheet only to have one |
| c050 | rule 17: "prefer Functions returning a count" | in a BUILD a callee's count that the caller discards cannot be seen by any TEST; the callee should be a Sub, or its result used |
| c050, c052 | rule 23: "its own GOAL, PRE, MODIFIES and ERR" and "a fixture where the callee's PRE fails and one where it gives 0 when Run checks n < 0" | the TASK format marks PRE and MODIFIES optional; the second sentence is hard to parse |
| c051 | rule 19: a blank cell in every column a `SKIP_IF IS_EMPTY` tests | with dictionary lookups this invites a guard pair (one when building, one at the lookup), and one of the two is always an equivalent mutant |
| c036, c038, c041 | DICT_GET and `SET_VALUE(cell, "")` | the prompt never says what DICT_GET gives for a missing key (a Long variable gets 0), or whether `SET_VALUE(cell, "")` leaves the cell empty (c034 used it; c035, c041, c042, c043 used `CLEAR(..., what=contents)`) |
| c037 | SORT | the prompt does not say whether SORT is stable or how it orders text; the spec has an ASSUME that ties come in no fixed order |
| c044 | TEST ASSERTIONS | `VALUE(cell) = "text"` compares with case, `COUNTIF` does not; this is said only under "= and <>" |
| c057 | rule 19: "Give each column that a SKIP_IF IS_EMPTY tests at least one blank cell (a "" boundary value in an early row, or +blank(<n>); ...)" | V059 wants the blank in every FIXTURE sheet that has the column, not once per spec: the second fixture file got V059 (same as c025) |
| c057 | rule 19: "repeat dictionary keys with +dupes(<n>) or values() counts of 2 or more" | a spec with several `DICT_ADD mode=sum` lines needs a key added at least twice through each such line, or `sum` to `overwrite` survives (c057 try 1, two survivors) |
| c057 | SEMANTICS: nothing says what DICT_GET gives for a key that is not there | the helper seeded all three dictionaries with 0 "to be safe", which made two seed lines equivalent mutants (see c036, c038, c041) |
| c057 | rule 22: "Only the run that adds a sheet can write to it, so a tool that rebuilds an output sheet on every run takes that sheet as an argument and ASSUMEs that it exists." | dense, and it conflicts with a plain "build a ... sheet" request; the helper understood it only through Example 4 |
| c057 | rule 19: stale=<n> | nothing says how to choose n; the helper worked out that it must exceed the number of rows the macro writes (stale=6 for 4 rows; same as c036, c037, c051) |
| c057, c068 | MODIFIES: lists "CLEAR what=all or formats" as needing the whole sheet | never says that `CLEAR what=contents` on a CELL, or SET_FORMULA, is allowed under `MODIFIES $ws["<header>"]`; the validator accepts both, so the helper only inferred it |
| c057 | rule 15: guard date comparisons "in a nested IF" | the SEMANTICS line for SKIP_IF says `SKIP_IF NOT IS_DATE(x)` guards x for the rest of the pass; rule 15 should name SKIP_IF (same as c019) |
| c057 | FIXTURE: "For values(...) the values move up, so the counts stay the same." | cryptic; the helper worked out from Examples 3 and 4 that `+boundary` must be a sub-multiset of `values(...)`, and that a boundary list covering every row makes the column fully fixed (see c026) |
| c053, c062 | rule 17: "a TEST can read a cell, not a MSG", against requests that say "tell me how many" | no example shows MSG in a TASK Function; the helpers wrote MSG plus RETURN(count), and c053 dropped `PERF screen_off` because a message box with screen updating off may not repaint |
| c057 | rule 5: the wrong-sheet TEST | for a TASK with two Worksheet arguments it does not say which to swap (a BUILD's wording does); the helper swapped the two |
| c057 | SORT `key=<col>` | stated only inside the DEDUPE paragraph ("cols= are sheet column numbers, as for SORT"); the helper used key=1 on a range that starts at column A |
| c062 | `VALUE(Sheet![Header]n) = "text"` in a TEST | its case- and space-exactness is said only for `=` and `<>` in expressions (see c044); c062 relies on it, and its 20 of 20 is consistent with it but does not prove it |
| c058, c070 | rule 22: "a tool that rebuilds an output sheet on every run takes that sheet as an argument and ASSUMEs that it exists" | when the request says "write a ... sheet" without "rebuilt", the prompt does not say which way to go (ADD_SHEET would leave a stale sheet on a re-run); it never says that "create if missing and rebuild" is impossible, so it reads as if some trick might exist |
